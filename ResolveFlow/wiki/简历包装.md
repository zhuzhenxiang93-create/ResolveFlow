# ResolveFlow 简历包装指南

本文档用于把 ResolveFlow 项目包装成简历、面试和项目展示中可讲清楚的经历。建议按真实实现描述，量化数据如果没有压测或标注集支撑，应写成“设计目标”或“在内置评测集上”。

包装重点：ResolveFlow 当前不建议只包装成“智能客服 Agent”，更适合定位为“多 Agent 客服编排/ Multi-Agent Customer Support”。项目已经支持细粒度意图识别、结构化路由决策、主辅 Agent 协同、RAG 知识增强、动态 Skills、异步记忆访问、Monitor 路由降权和 LLM-as-Judge 评测闭环。这是区分“普通聊天 Demo”和“可观测、可评测、可持续迭代 Agent 工程项目”的关键点。

## 2026-09-12 新增：受控 Agent 业务执行层

这轮之前，上面的内容只覆盖“能问答、能检索”的部分。这一轮补齐的是“能在授权范围内推进任务”这条更有工程深度的线，面试中更值得展开：

- **RAG × Action 打通**：把 Action 层的政策问答从“查一个独立的窄域 BM25 索引”改成真正复用主干的 ToolManager 混合检索链路（查询改写 + 向量/BM25 并行召回 + RRF + Qwen3 重排），并新增 `allowed_document_ids` 范围参数，让检索阶段本身（而不是拿到结果后再事后过滤）就把召回限定在订阅业务文档集合内——同一个 ChromaDB collection 里既有通用客服文档又有订阅业务文档时，也不会把范围外的文档答给用户。
- **最简 RBAC（JWT + 三角色）**：把原来硬编码的单一 demo 用户/审核员字符串，换成本地签发的 JWT（`user`/`reviewer`/`admin` 三角色，`core/auth.py`），支持真正的多个不同用户和多个不同审核员。这个改动顺带修好了一个真实缺陷：旧代码里 `reviewer == owner` 的自批检查因为两边永远是硬编码的不同常量，实际上从未被真正触发过；换成真实 subject 后这条检查第一次生效。
- **前端接入 Action 层**：Vue 前端新增身份令牌管理、模拟订单生成、结构化任务卡（状态/计划步骤/未完成目标）、用户确认与独立审核员批准/拒绝的完整交互，此前这些能力只能靠 CLI/curl 演示。
- **SQLite → PostgreSQL 迁移方案 + POC**：产出了迁移设计文档（事务边界映射、目标 schema、迁移步骤）和一个独立 POC（`agents/action_runtime_pg_poc.py`），在真实 Postgres 上验证了并发同幂等键仅落一行、advisory lock 真实串行化同一任务、异常回滚不留脏数据——不是只讲道理，是实测过的。

一句话版本：“在已有的多 Agent 问答系统上，加了一层受权限约束的业务执行能力——模型只能在授权工具和依赖关系内选择动作，写操作需要用户确认，高风险操作（退款）还需要独立人工审批，结果通过读库验证是否真的完成，而不是相信模型自己说完成了。”

### Q6：端到端 Agent 怎么评测？

**回答思路**

评测分两部分：

1. 意图识别评测：用标注用例计算 Accuracy 和 Macro-F1。
2. 端到端回复评测：真实调用 `Orchestrator.run()` 生成回复，再用 LLM-as-Judge 从四个维度打分。

四个维度是：

- `relevance`：是否回答用户问题。
- `accuracy`：信息是否准确。
- `completeness`：是否完整解决需求。
- `helpfulness`：用户能否据此行动。

评测器还会和上一轮结果对比，如果某个指标退化超过 5%，会标记为 regression，并生成优化建议。

## 30 秒项目 Pitch

> ResolveFlow 是一个面向复杂客服任务的多 Agent 客服编排运行时。我主要解决了七个工程问题：第一，意图识别用 LLM、Embedding 和 Pattern 三路融合，输出细粒度 intent、intent_group、来源分数和结构化实体；第二，知识库检索按意图触发，使用查询改写、并行召回和 LLM 重排增强业务类回复；第三，通过动态 Skills 把通用客服、技术支持和账单退款规范按 Agent 类型注入 prompt；第四，多轮对话用异步 Redis 工作记忆、ChromaDB 情景记忆和用户画像管理上下文；第五，多 Agent 通过 RoutingDecision 生成 primary_agent、supporting_agents 和 routing_reason，支持复合问题主辅协作；第六，Monitor 会根据成功率和延迟写回降权因子，动态影响后续路由；第七，用 LLM-as-Judge 做端到端评测和回归检测。整个系统可以用 Docker Compose 一键启动。
