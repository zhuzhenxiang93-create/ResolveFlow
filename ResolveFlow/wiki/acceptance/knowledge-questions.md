# 演示知识与多样问题

知识文件：data/knowledge/commerce_policy_v1.json。每条有稳定ID、业务域、版本、生效日期、来源。用户购买明细不进入公共知识库。

|ID / 类别|示例问题|
|goods-spec / 规格、兼容与排障|耳机能主动降噪吗？电脑找不到耳机，应该先排查什么？USB-C口用于什么？|
|goods-shipping / 配送与材料|显示签收但我没拿到，该提供什么？退货要准备哪些材料？能从规则文档知道我的包裹在哪吗？|
|goods-refund / 商品售后|只退鼠标优惠如何分摊？整单退款运费怎么处理？已发货为什么还不能直接说退款成功？|
|goods-invoice / 发票|开了票还可以申请售后吗？adjustment_required是否意味着税务红冲完成？|
|subscription-commerce-plan / 套餐周期|Basic和Pro价格有何区别？关闭续费之后本期权益还在吗？立即终止与停止续费有什么差别？|
|subscription-commerce-refund / 订阅退款|重复扣费退款会停掉会员吗？未使用续费扣款如何退款？已使用的年度会员能自动全额退吗？|
|commerce-payment / 异常人工处理|页面超时可以再点一次退款吗？待审核和退款处理中有什么区别？为什么需要另一名审核员？|

需要数据库而非知识库：我的订单买了什么、哪个账单重复、快递当前在哪里、发票状态、刚才退款结果。必须先用JWT确定本人记录，未知对象需消歧。

入库前后实际演示使用额外文档 goods-rfz9-manual v1；题目“RF-Z9型号的灯光模式如何切换？”；入库前无可靠答案，前端入库后显示三秒切换规则和来源。更新内容需同ID提升版本；可在测试文档使用v2改为五秒，检查旧片段被替换。不要修改执行性演示退款政策来伪造业务逻辑改变。
