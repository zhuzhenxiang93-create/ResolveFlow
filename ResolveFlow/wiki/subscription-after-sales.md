# 数字订阅售后闭环

## 产品边界

面向 Basic/Pro 数字订阅的本地售后原型，而非通用电商客服。
真实模型负责语义目标理解和业务工具选择；产品资料、订单、续费、扣款和退款均为内部模拟。
不支持物流、实物退货、真实支付渠道进度、真实价格和到期时间。需要人工处理不等于已经转接真人。

## 咨询与查询

政策咨询不需要订单号：套餐与权益、退订与续费、退款条件与进度、故障处理、授权与审批。
专用来源为 data/knowledge/subscription_service_v1.json，有稳定文档 ID 和版本。
完整 API 下复用主干 ToolManager 的查询改写+并行召回+RRF+Qwen3 重排链路，但通过 `allowed_document_ids`
把召回范围锁定在 `subscription_service_v1.json` 的文档 ID 集合内（ChromaDB `where` 子句 + 词法候选过滤），
原有泛客服资料（物流、通用退款政策等）仍不会混入订阅答案，但不再是"整库检索再事后丢弃"，而是检索阶段本身
就只看订阅域文档；无 Chroma/ToolManager 的环境（如纯 CLI）回退到本地 BM25Index，同样按文档 ID 限定范围。
直接引用文档原文，并将来源和检索时间持久化；这仍是小型受控知识库的抽取式回答，不是新检索算法，
也没有额外 LLM 润色调用。资料缺失不标为已回答。复合请求先显示政策答案，再为账户查询追问订单。

账户查询需要服务器绑定的用户和可访问订单：套餐、当前权益、扣退款计数、数字服务状态、自动续费状态。
查询不自动修改；结果包含具体业务事实，不只显示“已核验”。

## 办理与验证

权益修复：订阅与服务证据 -> 用户确认 -> 同步 -> 重新读库核验。
关闭自动续费：查询续费状态 -> 用户确认订单及操作 -> 关闭 -> 重新读库确认已关闭且套餐、权益、扣退款计数不变。
重复扣款退款：账单证据 -> 用户确认申请 -> 独立人工审批 -> 模拟退款 -> 核验计数。
关闭续费不立即移除当前权益、不退款；没有真实续费调度器，不能据此声称取消了真实扣款。
非重复扣款退款的政策可咨询，但执行资格仍需人工评估，不假装已经提交外部工单。

所有修改共用现有计划、权限、确认绑定、租约和状态机制。写入响应丢失先读取状态核对，不盲重试。
旧订单缺少 auto_renew 时不会猜测或自动补写；标记需要人工核实。可用 /seed 生成含该字段的新模拟订单。
旧已完成任务保持历史状态，不重写成新版本的正确结果。

## 运行

仓库根目录或后端目录：`make agent-chat`。输入 `/seed` 后用显示的订单号查询或办理。
可以先问“怎么退订？关闭后权益会消失吗？”，再输入 `/new 请关闭自动续费`。
完成后用 `/new 完整问题` 开始下个任务；不会继承旧修改授权。
CLI 的 /cancel 是取消任务，业务退订必须在问题中明确提出，二者不同。
API 的 /agent/tasks 和 /chat action 模式同样复用这些运行时能力。

离线测试：`make test`。
显式付费验收：从根目录运行 `PYTHONPATH=ResolveFlow .venv/bin/python ResolveFlow/scripts/check_subscription_live.py --live`，
或者在 ResolveFlow 目录下 `make subscription-live-check`。
该脚本限6次实际请求、SDK不重试、运行时不降级，专用执行器仅允许只读工具；使用隔离临时数据库。
报告保存到 data/eval/reports/agent/latest_subscription_live.json，3条开发者编写样例，不是准确率基准或生产评测。
没有供应商定价配置时成本为 null。CLI 本身尚无会话费用硬上限。
